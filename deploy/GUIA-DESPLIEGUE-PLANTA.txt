================================================================================
  QCS PRO LÁCTEOS — GUÍA DE DESPLIEGUE EN LA PLANTA (PASO A PASO)
================================================================================

REGLA DE ORO: en cada paso, PRIMERO se verifica con un comando y LUEGO se hace.
Si algo no coincide con lo que dice la guía, PARE y revise antes de seguir.

Convenciones:
  - Lo que está después de  PS>  se escribe en PowerShell de su PC (Windows).
  - Lo que está después de  $    se escribe en la consola del servidor (Ubuntu).
    (No escriba el  PS>  ni el  $ , solo lo que sigue.)
  - Lo que está entre < > se reemplaza por el valor real (sin los < >).
  - "Debe salir:" indica el resultado esperado.

Orden general (no cambie el orden):
  FASE A  En su PC, antes de ir a la planta ........................ (pasos 1-3)
  FASE B  Reconocer el servidor, SIN cambiar nada ................... (pasos 4-6)
  FASE C  Respaldar lo que hay ...................................... (paso 7)
  FASE D  Instalar la versión nueva ................................. (pasos 8-14)
  FASE E  Pruebas funcionales y de seguridad ........................ (pasos 15-17)
  FASE F  Dejar todo limpio para producción ......................... (pasos 18-20)
  FASE G  IP fija, apagón y tablets ................................. (pasos 21-24)
  FASE H  Entrega ................................................... (paso 25)
  ANEXOS  Volver atrás / clave olvidada / comandos útiles


================================================================================
FASE A — EN SU PC, ANTES DE IR A LA PLANTA
================================================================================

--- PASO 1. Código al día y sin cambios pendientes ----------------------------

Abra PowerShell en la carpeta del proyecto:
  Explorador de archivos -> C:\Users\jhon_\Documents\GitHub\qcs-lacteos
  -> clic en la barra de dirección -> escriba  powershell  -> Enter.

Verificar:
  PS> git status
  Debe salir: "nothing to commit, working tree clean"
  (Si hay cambios: haga el commit primero.)

--- PASO 2. Compilar desde cero -------------------------------------------------

  PS> Remove-Item -Recurse -Force dist, backend\dist -ErrorAction SilentlyContinue
  PS> npm run lint
      Debe salir: nada (sin errores).
  PS> npm run build
      Debe salir: "✓ built in ..."
  PS> cd backend
  PS> npm run build
      Debe salir: sin errores.
  PS> cd ..

Verificar que existen:
  PS> Test-Path dist\index.html, backend\dist\server.js
  Debe salir: True  True

--- PASO 3. Armar el paquete ----------------------------------------------------

  PS> tar -czf paquete-qcs.tar.gz dist backend/dist backend/package.json backend/database deploy

Verificar el contenido:
  PS> tar -tzf paquete-qcs.tar.gz | Select-String "index.html|server.js|init.sql|seed.sql|respaldo-bd.sh"
  Debe salir (entre otras): dist/index.html, backend/dist/server.js,
  backend/database/init.sql, backend/database/seed.sql, deploy/respaldo-bd.sh

  ¡OJO! seed_demo.sql y seed_demo_lotes.* también van en el paquete, pero
  NUNCA se ejecutan en la planta (son datos de prueba).

Copie a una USB:
  - paquete-qcs.tar.gz
  - esta guía (deploy\GUIA-DESPLIEGUE-PLANTA.txt)

Lleve anotado en papel:
  - Clave del usuario  ubuntu  del servidor (para sudo).
  - Datos del administrador real: nombre completo, código (ej. ADM-001), PIN y
    contraseña (mín. 8 caracteres).
  - Su celular con la hora correcta (se usa para poner la hora del servidor).

FASE B — RECONOCER EL SERVIDOR (SOLO MIRAR, NO CAMBIA NADA)

--- PASO 4. Entrar a la consola del servidor -----------------------------------

Opción 1 (recomendada para todo el despliegue): monitor y teclado conectados al
servidor. Inicie sesión con el usuario  ubuntu  y su clave.

Opción 2: por SSH desde su PC, conectado al MISMO WiFi de la planta.
  Para saber la IP del servidor, en la consola del servidor:
    $ ip -4 addr show
    (busque "inet 192.168.x.x" en la tarjeta que NO es "lo")
  Desde su PC:
    PS> ssh ubuntu@<IP_SERVIDOR>

  IMPORTANTE: el paso 21 (IP fija) se hace SIEMPRE con monitor y teclado,
  nunca por SSH (al cambiar la IP se corta la conexión).

--- PASO 5. Anotar cómo está instalado -----------------------------------------

Copie cada comando y ANOTE el resultado en la tabla del final de este paso.

a) Dónde corre el backend:
   $ ps aux | grep -i [n]ode
   $ sudo ls -l /proc/$(pgrep -f "node.*server" | head -1)/cwd
   Esperado (como en el ensayo): /home/ubuntu/backend

b) Cómo arranca (servicio):
   $ systemctl list-units --type=service | grep -i -E "lacteo|qcs|node|backend"
   $ systemctl is-enabled lacteos
   Esperado: lacteos.service ... running   y   enabled
   $ cat /etc/systemd/system/lacteos.service
   Anote WorkingDirectory y ExecStart.

c) nginx:
   $ ls /etc/nginx/sites-enabled/
   $ grep -R -n "proxy_pass" /etc/nginx/sites-enabled/
   Esperado: proxy_pass http://127.0.0.1:3001;
   (Si dice http://localhost:3001 o http://0.0.0.0:3001, NO use HOST=127.0.0.1
    en el paso 11 sin antes cambiarlo a 127.0.0.1.)

d) Carpetas del proyecto:
   $ ls -la ~ ~/backend
   Esperado: ~/dist (frontend), ~/backend/dist, ~/backend/node_modules,
   ~/backend/.env, ~/backend/package.json

e) Configuración (.env) SIN mostrar claves:
   $ sed -E 's/(PASSWORD|SECRET|DATABASE_URL)=.*/\1=***oculto***/' ~/backend/.env
   Anote qué variables existen (PORT, DATABASE_URL, JWT_SECRET, TRUST_PROXY,
   HOST, NODE_ENV, COOKIE_SECURE, HTTPS_ENABLED...).
   COOKIE_SECURE y HTTPS_ENABLED NO deben estar en true (la planta usa HTTP).

f) Base de datos:
   $ sudo -u postgres psql -l
   Anote el nombre de la base (en el ensayo: qsc_lacteos) y el dueño (superu).
   $ URL=$(grep ^DATABASE_URL ~/backend/.env | cut -d= -f2- | tr -d '"' | tr -d '\r')
   $ echo "$URL" | sed -E 's#(://[^:]+:)[^@]*@#\1****@#'
   Debe salir algo como: postgres://superu:****@localhost:5432/qsc_lacteos
   Anote el usuario (lo que va entre // y :) y la base (lo del final).
   $ psql "$URL" -Atc "select current_user, current_database()"
   Debe salir: <usuario>|<base>   (confirma que la clave del .env funciona)
   $ sudo -u postgres psql -Atc "select rolname, rolsuper from pg_roles where rolname='<USUARIO_BD>'"
   Debe salir: <USUARIO_BD>|f   (f = no es superusuario; correcto)

g) Versiones y herramientas:
   $ node -v
   $ psql --version
   $ which pg_dump pg_restore pg_isready
   Deben existir los tres (vienen con PostgreSQL).

h) Hora:
   $ timedatectl
   Anote "Time zone" y si la fecha/hora coinciden con su celular.

i) Red:
   $ ip -4 addr show
   $ ip route | grep default
   $ ls /etc/netplan/ && sudo cat /etc/netplan/*.yaml
   Anote: tarjeta (ej. enp2s0), IP actual, router (gateway), y si el .yaml
   dice dhcp4: false con "addresses" (IP fija ya configurada) o dhcp4: true.

j) Espacio en disco:
   $ df -h /
   Debe haber al menos 2 GB libres.

  $ tar -tzf ~/paquete-qcs.tar.gz | grep -c .
  Debe salir: el archivo con su tamaño, y un número de archivos mayor que 50.

--- PASO 9. Detener el backend --------------------------------------------------

  $ sudo systemctl stop lacteos
Verificar:
  $ systemctl is-active lacteos
  Debe salir: inactive

--- PASO 10. Reemplazar los archivos -------------------------------------------

  $ rm -rf ~/nuevo && mkdir -p ~/nuevo
  $ tar -xzf ~/paquete-qcs.tar.gz -C ~/nuevo
  $ ls ~/nuevo ~/nuevo/backend
    Debe salir: dist  backend  deploy   /   database  dist  package.json

  $ rm -rf ~/dist ~/backend/dist ~/backend/database ~/deploy
  $ mv ~/nuevo/dist ~/dist
  $ mv ~/nuevo/backend/dist ~/backend/dist
  $ mv ~/nuevo/backend/database ~/backend/database
  $ cp ~/nuevo/backend/package.json ~/backend/package.json
  $ mv ~/nuevo/deploy ~/deploy
  $ rm -rf ~/nuevo

  (node_modules NO se toca: las librerías del backend no cambiaron.)

Verificar:
  $ ls ~/dist/index.html ~/backend/dist/server.js ~/backend/database/init.sql ~/deploy/respaldo-bd.sh
  Debe salir: las 4 rutas sin error.
  $ ls ~/backend/dist/controllers/
  NO deben aparecer batchController.js, executionController.js ni
  packagingController.js (eran de la versión anterior).

--- PASO 11. Revisar y completar el .env ---------------------------------------

Ver variables actuales (sin claves):
  $ sed -E 's/(PASSWORD|SECRET|DATABASE_URL)=.*/\1=***oculto***/' ~/backend/.env

Agregar SOLO las que falten (cada línea verifica antes de agregar):
  $ grep -q '^TRUST_PROXY=' ~/backend/.env || echo 'TRUST_PROXY=loopback' >> ~/backend/.env
  $ grep -q '^HOST=' ~/backend/.env || echo 'HOST=127.0.0.1' >> ~/backend/.env

  (HOST=127.0.0.1 solo si en el paso 5c nginx usa proxy_pass http://127.0.0.1:3001)

Largo del JWT_SECRET:
  $ grep ^JWT_SECRET ~/backend/.env | cut -d= -f2- | tr -d '"\r\n' | wc -c
  Si sale 32 o más:
  $ grep -q '^NODE_ENV=' ~/backend/.env || echo 'NODE_ENV=production' >> ~/backend/.env
  Si sale menos de 32: NO agregue NODE_ENV=production (el backend no arrancaría).
  Puede generar un secreto nuevo y largo así:
  $ NUEVO=$(openssl rand -hex 32); sed -i "s/^JWT_SECRET=.*/JWT_SECRET=$NUEVO/" ~/backend/.env
  y luego sí agregar NODE_ENV=production.
  (Cambiar el JWT_SECRET solo obliga a todos a ingresar de nuevo.)

Que NO estén activos:
  $ grep -E '^(COOKIE_SECURE|HTTPS_ENABLED)=' ~/backend/.env
  Si aparece alguno con "true", cámbielo a false o borre esa línea:
  $ nano ~/backend/.env      (Ctrl+O, Enter para guardar; Ctrl+X para salir)

Proteger el archivo:
  $ chmod 600 ~/backend/.env

Verificar resultado final:
  $ sed -E 's/(PASSWORD|SECRET|DATABASE_URL)=.*/\1=***oculto***/' ~/backend/.env
  Debe tener: PORT=3001, DATABASE_URL, JWT_SECRET, TRUST_PROXY=loopback,
  HOST=127.0.0.1 y (si aplica) NODE_ENV=production. Cada variable UNA sola vez.

--- PASO 12. Base de datos nueva y limpia --------------------------------------

Verificar que nadie está conectado (el backend ya está detenido):
  $ sudo -u postgres psql -Atc "select count(*) from pg_stat_activity where datname='$BD'"
  Debe salir: 0
  (Si sale más de 0:  sudo systemctl stop lacteos  y repita.)

Borrar y crear (el dueño debe ser el usuario de la aplicación):
  $ sudo -u postgres dropdb "$BD"
  $ sudo -u postgres createdb -O "$USUARIO_BD" "$BD"

Crear estructura y datos iniciales (CON EL USUARIO DE LA APLICACIÓN, no con
postgres, para que las tablas queden a su nombre):
  $ psql "$URL" -v ON_ERROR_STOP=1 -f ~/backend/database/init.sql
  $ psql "$URL" -v ON_ERROR_STOP=1 -f ~/backend/database/seed.sql
  Debe salir: solo líneas como CREATE TABLE, INSERT..., COMMIT. NINGÚN "ERROR".

  ¡NO ejecute seed_demo.sql!

Verificar:
  $ psql "$URL" -Atc "select count(*) from information_schema.tables where table_schema='public' and table_type='BASE TABLE'"
  Debe salir: 28
  $ psql "$URL" -Atc "select codigo_empleado, rol from usuarios"
  Debe salir SOLO: SA-001|superadmin
  $ psql "$URL" -Atc "select count(*) from productos"
  Debe salir: 7
  $ psql "$URL" -Atc "select count(*) from lotes_produccion"
  Debe salir: 0
  $ psql "$URL" -Atc "select tablename, tableowner from pg_tables where schemaname='public' and tableowner <> current_user"
  Debe salir: NADA (todas las tablas son del usuario de la aplicación).

--- PASO 13. Poner la hora del servidor ----------------------------------------

Mire la hora EXACTA en su celular en este momento y escríbala (formato
AAAA-MM-DD HH:MM:SS, 24 horas). NO copie la fecha del ejemplo.
  $ sudo timedatectl set-timezone America/Bogota
  $ sudo timedatectl set-ntp false
  $ sudo timedatectl set-time "<AAAA-MM-DD HH:MM:SS>"
Verificar:
  $ timedatectl
  Debe salir: Time zone: America/Bogota (-05, -0500) y la fecha/hora iguales a
  su celular (diferencia de pocos segundos).

--- PASO 14. Arrancar y verificar el backend -----------------------------------

  $ sudo systemctl start lacteos
  $ sleep 3
  $ systemctl is-active lacteos
  Debe salir: active
  $ journalctl -u lacteos -n 15 --no-pager
  Debe salir:
    [server] API escuchando en http://127.0.0.1:3001 ...
    [server] Esquema de base de datos verificado.
  y NINGÚN "ERROR" ni "FATAL".

  $ curl -s http://127.0.0.1:3001/api/health ; echo
  $ curl -s http://localhost/api/health ; echo
  Ambos deben responder: {"status":"ok","database":"up",...}

  $ ss -ltn | grep 3001
  Debe salir: 127.0.0.1:3001   (NO 0.0.0.0:3001)

  $ sudo systemctl status nginx --no-pager | grep Active
  Debe salir: active (running)

--- PASO 16. Pruebas de seguridad ----------------------------------------------

a) Puerto directo cerrado (desde la tablet):  http://<IP_SERVIDOR>:3001
   Debe: NO abrir (error de conexión).

   (Si sale "UPDATE 0" es porque no cerró ningún lote en el paso 15.)

g) El usuario de la aplicación NO es superusuario:
   $ psql "$URL" -Atc "select rolsuper from pg_roles where rolname = current_user"
   Debe salir: f

h) Cabecera de seguridad CSP:
   $ curl -sI http://localhost/ | grep -i content-security
   Debe salir: Content-Security-Policy: default-src 'self'; ...

i) Claves guardadas cifradas (nunca en texto):
   $ psql "$URL" -Atc "select codigo_empleado, left(pin_hash,7) from usuarios"

--- PASO 21. IP fija (CON MONITOR Y TECLADO, NO POR SSH) -----------------------

Verificar primero:
  $ sudo cat /etc/netplan/*.yaml
  Si ya dice  dhcp4: false  y  addresses: [<IP>/24]  -> YA ES FIJA. Salte al
  paso 22.

Si dice dhcp4: true:
  a) Elija la IP (la del acceso directo de la planta es 192.168.18.10; si el
     servidor ya tiene una IP que todos usan, mantenga esa):
     $ ping -c 3 <IP_ELEGIDA>
     Si responde y NO es este mismo servidor: esa IP está ocupada, elija otra.
  b) Cree el archivo (cambie tarjeta, IP y router por los anotados en el paso 5i):
     $ sudo nano /etc/netplan/99-ip-fija.yaml
     Escriba EXACTAMENTE (respete los espacios, no use tabulador):

network:
